# 실제 모델과 사용자 업무 레시피

## 한 문장에서 실제 앱 결과까지

`NO_TOUCH_MODEL=chatgpt npm run live`는 eve의 공식 `chatgpt()` 모델을 사용합니다. ChatGPT 구독 로그인은 공식 eve TUI의 `/login chatgpt`로 설정하며 자격 증명은 OS secret store에 저장됩니다. 로그인은 로컬 개발 전용입니다. 이 저장소의 조건부 모델 선택 코드는 이미 helper를 사용하므로 CLI의 자동 코드 수정 경고가 나면 helper 분기를 유지하고 연결 응답을 확인합니다. 토큰을 프로젝트나 공개 Git에 복사하지 않습니다.

다음 요청을 실제 모델·웹 채팅·실제 Mac에 연결해 검증했습니다.

> 회의 메모 만들고, 내일 오후 3시(서울)에 알림 추가하고, 최근 파일 보여줘.

모델은 `office_work`에 타입이 있는 단계를 전달합니다. 서버가 서울 달력 기준 내일을 확정하고, 실행할 앱·번들 ID·전용 범위·메모 내용·절대 일정을 먼저 보여 줍니다. 사람이 계획을 승인한 다음 Notes 신규 메모, EventKit 일정 commit/별도 프로세스 재조회, Finder 파일 카드가 차례로 실행됩니다. 모델은 검증된 결과를 받아 한국어로 보고합니다. 고정 예제 모델은 이 경로의 증거로 사용하지 않았습니다.

[실제 모델 E2E 결과](evidence/real-model-result.json)와 [웹 결과 화면](evidence/real-model-web-completed.png)을 참조하세요. `npm run demo`의 기본 모델은 계속 오프라인 고정 시나리오입니다. Gateway·OpenAI 직접 API는 설정 경로가 있지만 이 검증에서 호출한 모델은 ChatGPT 구독 경로입니다.

## 저장 가능한 레시피

“업무 레시피 만들기” 또는 채팅으로 이름·단계·화면을 요청합니다. 예를 들어 신규 회의 메모 → 내일 15시 서울 알림 → 최근 파일 조회를 제안할 수 있습니다.

1. 스키마가 지원 capability와 입력·경로·목적지만 허용하는지 검사합니다. 코드·shell·새 bundle ID·임의 권한·새 네트워크 전송은 거부됩니다.
2. 별도 Node 프로세스의 새 임시 fixture에서 같은 단계를 실제 실행해 테스트합니다. macOS 앱에는 아무 작업도 하지 않습니다. 새 native capability 자체의 검증을 대체하는 테스트가 아닙니다.
3. 필요한 앱·권한 범위·단계·`cards` 또는 `compact` 표시와 테스트 결과를 보여 주고 저장 승인을 기다립니다.
4. 승인된 데이터만 로컬 `recipes/<hash>.json`에 저장합니다. 저장만으로 앱이 실행되거나 권한이 추가되지 않습니다.
5. “이 레시피 실행”을 누르면 저장된 동일 계획으로 새 실행을 준비하며, 다시 계획 확인을 받습니다. ‘내일’은 저장한 날이 아니라 실행하는 날의 서울 달력 기준으로 계산됩니다.

화면 변경은 검증된 `cards`/`compact` 레이아웃 데이터에 한정합니다. 런타임에 앱 소스를 다시 쓰거나 무제한으로 새 도구를 설치하지 않습니다. 새 앱은 별도 capability 개발·테스트·권한 확인이 필요합니다.

## 승인과 중복 방지

실제 모델은 기존 네 개의 직접 실행 도구를 호출해 계획 확인을 우회할 수 없습니다. agent-wide 정책이 거부하며 `office_work`만 앱 실행 입구로 사용합니다. `work_history`는 기록·레시피 조회와 남은 단계 취소만 할 수 있습니다.

한 user turn에는 하나의 불변 계획을 사용합니다. 작업 ID, 서버 turn ID, 계획, 실행 모드와 단계별 결과를 로컬에 기록합니다. 완료 단계는 Workflow replay와 예약 ledger의 검증된 결과를 사용합니다. 같은 turn에 다른 계획을 만들어 거절·실패를 우회할 수 없습니다. 동일 계획의 결과 불명이 남아 있으면 새 작업도 차단합니다.

파일은 초기 계획에서 정확한 이름·fingerprint를 확정하고, 실제 변경 직전에 **별도의 파일 승인**을 받습니다. 해당 입력 해시를 단계에 저장하고 실행 시 확인합니다. 이후 원본 fingerprint를 다시 검사하며 달라졌으면 멈춥니다. Trash는 전용 샘플 하위 폴더이고 외부 공유는 로컬 preview뿐입니다.

## 작업 기록·취소·복구

“작업 기록” 버튼과 `work_history`로 단계별 `pending/started/verified/denied/uncertain` 결과를 확인합니다. 남은 단계 취소는 별도 영속 취소 표시와 기록에 남고 이후 단계의 쓰기를 막습니다. 이미 시작한 현재 동작은 완료될 수 있습니다. 이미 만든 메모·알림을 자동 삭제하는 undo가 아닙니다. 완료 항목 정리는 별도의 삭제 승인 대상입니다.

- 승인 대기: 같은 세션 URL로 돌아갑니다. 같은 로컬 `.eve`와 데이터 디렉터리를 보존하고 `--resume`으로 서버를 시작합니다.
- 완료된 단계: 그대로 유지합니다. 같은 작업 재개에서 다시 만들지 않습니다.
- `uncertain`: 새 작업이나 다른 내용으로 우회하지 않습니다. 기록의 예상 앱·제목·일정·파일을 실제 읽기 상태와 대조합니다. 예약 ledger가 `verified`이면 결과를 재사용할 수 있고, 시작만 기록돼 있으면 자동 재실행을 차단합니다.
- 로컬 정합성 확인: `.demo-native/data/jobs`와 `operations`를 백업한 뒤 사람이 실제 결과를 확인합니다. 이 버전에는 임의로 ledger를 지우거나 불명 작업을 강제 성공 처리하는 UI가 없습니다. 확인할 수 없으면 취소하고 결과 불명 기록을 유지합니다.

네이티브 실행기와 웹 프로세스의 실패를 하나의 DB 트랜잭션으로 되돌리는 기능은 아닙니다. 저장소 손실·전원 장애·다른 사용자의 동시 UI 변경까지 정확히 한 번의 효과를 보장하지 않습니다.

## No-Touch 검증

실행기에는 물리 키·좌표·focus·headed API가 없습니다. Notes는 부동 새 창 대신 준비된 기본 창과 전용 폴더를 사용합니다. Finder는 `NSWorkspace.activates=false`입니다.

실제 모델 웹 → 세 앱 실행의 조작 없는 측정 구간에서 AppKit 앱 활성화 이벤트 0회, 25ms 간격의 커서 관찰에서 위치 변경 0회를 확인했습니다. 사용자가 동시에 앱을 바꾸거나 마우스를 움직인 앞선 관찰은 성공 근거에서 제외했습니다. 커서 관찰은 샘플링이므로 모든 미세한 이동을 증명하는 수학적 보장은 아닙니다. 고정 창이 닫히거나 선택 폴더가 달라지면 다른 개인 창을 대신 조작하지 않고 멈춥니다.


샘플/실제 모드와 데이터 디렉터리별로 별도 checkout을 사용하세요. 실행기는 `.eve/no-touch-scope.json`에 범위를 고정하며, 다른 모드나 경로로 같은 retained 상태를 재개하면 중단합니다. 저장소·세션을 자동 초기화하지 않습니다. `npm run live`의 기본 모델은 로그인한 ChatGPT 구독 모델이고, 고정 시나리오는 `NO_TOUCH_MODEL=rehearsal`을 명시할 때만 사용합니다.
