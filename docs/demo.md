# 2분 발표와 실행 절차

## 사전 준비

1. `npm ci`, `npm test`, `npm run test:integration`을 완료합니다.
2. 새 빈 `.demo-presentation-날짜`를 지정해 `npm run demo`를 실행합니다. 이전 샘플 파일을 자동 복원하거나 삭제하지 않습니다.
3. http://127.0.0.1:3000 에 직접 접속합니다. 브라우저를 자동으로 열거나 발표자의 다른 앱을 활성화하지 않습니다.
4. “샘플 리허설 / 실제 macOS 앱 비활성화 / 고정 오프라인 모델” 표시를 확인합니다.
5. 서버 로그는 선택한 데이터 디렉터리의 `logs/`에 있습니다 (기본값 `.demo/logs`). 샘플 상태와 세션은 공개하지 않습니다.

## 0:00–0:20 — 범위와 요청

“현재는 안전한 샘플 모드입니다. macOS 앱을 직접 조작했다고 주장하지 않습니다. 실제 eve durable 실행·웹 채팅·승인 대기를 보여 드립니다.”

예제 버튼을 눌러 다음 요청을 넣고 전송합니다.

> 샘플 회의 메모를 작성하고, 2026년 11월 19일 오후 3시(서울)에 준비 알림을 추가해 줘. 최신 파일을 카드로 보여 주고 가장 최근 파일을 Archive로 이동해 줘.

오프라인 예제는 고정 내용·날짜를 사용하는 스크립트입니다. 진짜 자연어 계획은 자격 증명을 별도로 구성한 Gateway 모델로 평가해야 합니다.

## 0:20–0:50 — 결과와 근거

샘플 메모 저장 확인, 서울 시간대의 알림, 최신 파일 카드 순서를 보여 줍니다. 파일은 이름·크기·수정 시각·fingerprint가 표시됩니다. 원본 파일은 아직 그대로입니다. 네이티브 Finder 창이 아니라 파일 카드 UI입니다.

## 0:50–1:20 — 승인과 재개

대기 카드의 정확한 파일명·목적지·동작·fingerprint를 읽습니다. 새로고침하여 같은 세션의 승인이 복구되는 것을 보여 줍니다. 세션 URL을 유지해야 합니다.

발표 중 서버 재시작까지 보여 주려면 `Ctrl+C` 후 **같은 데이터 디렉터리와 같은 `.eve`**로 `npm run demo`를 다시 실행합니다. 동일한 세션 URL을 다시 엽니다. 메모·알림을 다시 생성하면 안 됩니다. 자동 통합 테스트는 이 경로를 검증합니다.

## 1:20–1:45 — 명시적 결정

“거절”을 누르면 변경 도구가 rejected로 끝나며 파일은 그대로입니다. 또는 “이 변경 승인”을 눌러 샘플 Archive로 이동된 결과를 보여 줍니다. 이 버튼은 샘플 파일 변경을 실제로 수행합니다. 승인은 말이나 모델 판단으로 자동 대체하지 않습니다.

## 1:45–2:00 — 확장

관측 가능한 trace와 승인 정책을 유지한 채 격리 macOS 계정에서 네이티브 recipe를 검증하는 다음 단계를 설명합니다. 현재 네이티브 앱 E2E와 외부 공유는 미검증·미구현임을 다시 명확히 합니다.

## 중단과 복구

- 접근성 권한 없음: `npm run preflight` 결과만 제시합니다. 앱 제어를 시도하거나 설정을 열지 않습니다.
- STALE_REF: 내부 제한된 복구가 실패하면 중단하고 새로운 관찰을 요구합니다.
- AMBIGUOUS_TARGET: 창이나 컨트롤을 임의로 고르지 않습니다.
- OUTCOME_UNCERTAIN / DESKTOP_BUSY: 생성이나 변경을 다시 요청하지 않습니다. 상태를 읽어 사람이 결과를 확인합니다. ledger·lock을 자동 삭제하지 않습니다.
- 파일 fingerprint 변경: 새 카드를 조회하고 새 명시적 승인을 받습니다.
- 공유: `.share-preview/*.json`만 생성됩니다. 외부로 보냈다고 설명하지 않습니다.

종료는 `Ctrl+C`입니다. 로그·세션·샘플은 남으며 사용자 앱이나 OS 설정의 원복 작업은 필요하지 않습니다. 실제 앱을 건드린 적이 없기 때문입니다.
