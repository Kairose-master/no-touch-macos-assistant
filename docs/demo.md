# 2분 발표와 운영 절차

## 사전 준비

실제 Mac 발표는 [native.md](native.md)의 빌드·권한·전용 폴더/목록·창 고정 준비를 먼저 마칩니다. 실제 모델 발표는 `NO_TOUCH_MODEL=chatgpt npm run live` 후 http://127.0.0.1:3000 을 직접 열어 **LOCAL NATIVE** 배너를 확인하세요. 준비 중의 창 선택과 권한 대화상자는 발표 런타임과 구분합니다. 사용자 브라우저를 자동 활성화하지 않습니다.

안전한 가짜 앱 리허설은 새 빈 `NO_TOUCH_DATA_DIR="$PWD/.demo-presentation-2" npm run demo`로 실행합니다. 이때 **LOCAL REHEARSAL**이며 실제 앱 비활성화라고 설명합니다. 샘플 상태를 지우거나 원래 파일을 자동 복원하지 않습니다.

## 0:00–0:20 — 범위와 요청

“전용 샘플만 사용하는 로컬 Mac 데모입니다. 메모는 headless CLI, 일정은 EventKit, Finder 파일은 관찰과 제한된 파일 API를 사용합니다. ChatGPT 구독 모델이 요청을 계획하며 실제 결과를 보고합니다. 오프라인 모델을 선택한 경우에는 고정 시나리오라고 구분합니다.”

예제 버튼 → 요청 보내기를 누릅니다. 실제 모델 예제는 내일 오후 3시 서울을 서버가 확정해 계획에 표시합니다. 고정 오프라인 모델을 선택한 live는 2030-11-19, fixture는 2026-11-19 예제입니다. 실제 모델을 별도 구성했다면 애매한 시간은 먼저 확인해야 합니다.

## 0:20–0:50 — 실제 결과

메모 내용 재조회, 일정·시간대·알람 commit 재조회, 최신 파일 카드 순서를 보여 줍니다. 파일명·수정 시간·fingerprint가 표시되고 원본 파일은 아직 그대로입니다. 데모 중 시스템의 전면 앱과 커서가 바뀌지 않는 검증 결과를 설명합니다. Notes 기본 창을 이미 준비한 이유도 간단히 설명할 수 있습니다.

## 0:50–1:20 — 승인 대기와 복구

정확한 파일명·목적지·fingerprint 승인 카드를 읽습니다. 현재 세션 URL을 유지하고 새로고침하면 같은 승인 요청이 복구됩니다. 신규 요청을 다시 보내지 않습니다. fixture 통합 테스트에서는 같은 로컬 Workflow 상태의 서버 재시작 후 동일 interaction 복구도 검증했습니다.

## 1:20–1:45 — 명시적 결정

“거절”이면 파일은 그대로입니다. “이 변경 승인”이면 전용 샘플 파일을 Archive로 이동합니다. 거절 시나리오를 보인 다음 새 시나리오를 요청하면 실제 샘플 메모와 일정이 추가 생성됩니다. 사용자의 채팅 문장을 승인 버튼의 응답으로 대체하지 않습니다.

## 1:45–2:00 — 다음 단계

OTel metadata trace·durable 승인 상태·중복 차단을 짚고, “업무 레시피 만들기”의 격리 테스트·저장 승인·재사용과 cards/compact 화면 변경을 짧게 보여 줍니다. 다중 사용자 인증·Mac worker 큐·외부 공유 영수증은 다음 단계입니다. 외부 공유는 현재 로컬 preview뿐입니다.

## 실패와 종료

권한 없음·고정 창 불일치·복수 후보·불완전 snapshot이면 중단합니다. STALE_REF/AMBIGUOUS_TARGET도 safe/not_delivered일 때만 새 관찰로 제한 복구하며 물리 키·headed로 전환하지 않습니다. OUTCOME_UNCERTAIN/DESKTOP_BUSY는 새 내용·세션으로 재실행해 우회하지 말고 실제 상태를 확인하세요. fingerprint가 달라지면 새 카드와 새 승인이 필요합니다.

`Ctrl+C`로 두 서버를 종료합니다. 선택된 데이터 디렉터리의 logs와 `.eve` 세션, 실제 NoTouch 샘플 항목·허용한 권한은 남습니다. 삭제·권한 원복은 자동 수행하지 않습니다.
